# CLAUDE.md

## Project Overview

ModbusRTUSniffer-PySide is a PySide6 GUI application that sniffs, parses, and visualizes Modbus RTU protocol traffic on serial connections. It displays real-time register/coil values organized by slave device address, with breakpoint support for debugging.

## Architecture

Single-threaded Qt application using QTimer-based polling (no background threads). Follows an MVC-like pattern with PySide6 signal-slot coupling.

**Data flow:** Serial port → `SerialReader` → `ModbusParser` (pymodbus internals) → callbacks → `ModbusParserViewer` → per-device widgets

### Source Files

All source files are in the project root (flat structure):

| File | Role |
|------|------|
| `main.py` | Entry point; creates QApplication and main window |
| `modbus_parser.py` | Modbus RTU packet parsing via pymodbus FramerRTU internals |
| `serial_reader.py` | Serial port I/O (`SerialReader`) and mock reader (`SerialReaderTest`) |
| `tools.py` | Modbus function code table definitions |
| `modbus_parser_viewer.py` | Main window / controller; orchestrates parsing and UI updates |
| `device_addr_widget.py` | Per-slave-address container with Registers and Bits tabs |
| `device_value_table.py` | 16x16 grid table for register/coil values with color animation |

## Dependencies

- **Python 3.10+** (uses `match`/`case` statements)
- **PySide6** — Qt bindings
- **pymodbus==3.7.3** — CRITICAL: must be exactly 3.7.3; uses internal non-public parsing APIs that break across versions
- **pyserial** — serial port communication
- **dotenv** — environment variable loading

No `requirements.txt` or `pyproject.toml` exists. Install manually:
```
pip install PySide6 pymodbus==3.7.3 pyserial python-dotenv
```

## Running

```bash
# Normal mode (requires serial device)
python main.py

# Test mode (mock serial data, no hardware needed)
TEST_SERIAL=1 python main.py
```

## Testing

No formal test framework (pytest/unittest). Testing is done via:

1. **`TEST_SERIAL=1`** environment variable activates `SerialReaderTest` with 16 hardcoded Modbus RTU packets covering all supported function codes
2. **`modbus_parser.py`** has a `main()` function with inline test data
3. **`Example Packets.raw`** can be imported through the UI for replay testing

## Code Conventions

- **Naming:** snake_case for functions/variables, PascalCase for classes
- **Type hints:** Used throughout method signatures
- **Signals:** PySide6 Signal/Slot for inter-widget communication (`msg_show_req`, `breakpoint_req`)
- **Widget creation:** Lazy — `DeviceAddrWidget` instances created on-demand when a new slave address is seen
- **UI files:** `.ui` files designed in Qt Designer; corresponding `*_ui.py` generated (never hand-edit generated files)

## Key Implementation Details

- Parser uses two `FramerRTU` instances (client and server) to distinguish requests from responses
- `WriteSingleRegister`/`WriteSingleCoil` have identical request/response structure — special-cased in parser
- Monkey-patches `FramerRTU.processIncomingPacket` at runtime to intercept parsed packets
- Color-coded cells: green = read, red = write, fading over 10 seconds
- Raw packet view uses QPlainTextEdit block indices for click-to-navigate
- Currently treats Input Registers = Holding Registers, and Coils = Discrete Inputs (same memory model)

## Known Limitations / TODOs

- No separate handling of holding vs. input registers
- No separate values for read vs. write operations
- Fragile dependency on pymodbus internals — version upgrades may break parsing
